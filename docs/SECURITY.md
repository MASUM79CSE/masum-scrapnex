# MASUM SCRAPNEXS — Security and privacy design

Phase 01 threat model and release requirements, not an audit or security claim. Trust the packaged extension and its validated internal state; treat all site DOM/text/URLs/attributes, imports and transport payloads as untrusted. `activeTab` indicates browser access, not consent for bulk collection or legal entitlement to reuse data.

## Permissions and data lifecycle

| Permission/capability | Intended use and policy |
|---|---|
| `activeTab` | Temporary access to the tab invoked by the user; verify before each injection and when route/origin changes. |
| `scripting` | Inject bundled isolated-world script into the authorized top-level document, never arbitrary code. |
| `sidePanel` | Chrome workspace; no scanning merely because it is open. |
| `storage` | Extension-local settings. Avoid exposing settings to content scripts where platform APIs allow trusted-context access restriction. |
| Save/copy | User action for file save or clipboard; start with ordinary browser mechanisms. Any extra downloads/clipboard permission requires a documented necessity and review. |

No default host grants, browsing history, `debugger`, network interception, `externally_connectable` or public bridge. No upload, analytics, sync, remote fonts/assets or remote code in production; site network activity from user-approved standard navigation or scrolling is not extension telemetry. Do not read cookies, auth headers, page storage, form values (hidden or visible) or password fields. Default collection excludes sensitive inputs, hidden nodes, and iframe content. Users may still collect sensitive information displayed by a site; warn before saving/sharing such datasets. Keep full route/query only transiently when required, redact query/fragment and credentials from history by default, and avoid persisting path where unneeded. A requested extracted hyperlink may itself contain sensitive parameters; treat values as user data, warn in preview/export, and do not use them as telemetry or diagnostics. Storage is local to the browser profile, not a guarantee of encryption at rest; exports are plaintext files or ordinary spreadsheets.

## Controls against untrusted input

- **Messages and callbacks:** validate schemas, kinds, sizes, string lengths, IDs and allowable transitions before use. Match runtime sender ID plus extension page path or expected content tab/frame/document/epoch; do not trust payload-supplied sender data. No `window.postMessage` bridge. Only extension UI can authorize commands; page-agent reports cannot grant permission. Cancel rejects stale responses and invalidates pending step tokens.
- **Rendering and DOM:** treat site text as text (React text nodes), never `innerHTML`, inline handlers, `eval` or `Function`. URL parser plus `http:`/`https:` allowlist for web navigation; reject `javascript:`, `data:`, `file:`, extension URLs and embedded credentials for navigation. Values displayed as plain text unless explicitly opened; no embedded external images and no automatic link previews. Add no-opener/no-referrer when opening an explicit external link. Restrict attribute allowlist to descriptive fields and reviewed `data-*` names; reject event handlers, style, form-value-like and token-like attributes. Enforce CSP with bundled code only and verify production artifacts do not rely on dev scripts.
- **Picker and controls:** prefer selection overlay in an isolated widget that does not mutate site elements. Gesture boundaries and teardown on Escape, route change, disconnect, or stop; validate target position/identity again immediately before an action. Never auto-click form submits, account controls or ambiguous controls. No CAPTCHA, paywall, login, rate-limit or anti-bot evasion. User chooses an origin and bounded action; cross-origin redirects pause without extraction and browser restrictions are never overridden.
- **File and clipboard:** normalize file basenames, remove path separators/control characters, block device names and trailing problematic characters, bound length and append fixed extension. As CSV or tabular clipboard, detect formula-leading characters `=`, `+`, `-`, `@` and leading tab/CR/LF, including formula prefixes reached through leading whitespace/control characters; neutralize as text before serialization. Quote fields separately, including headers. Preserve actual typed finite numeric values where safe; test spreadsheet handling of strings that look like numbers and formulas. In XLSX, use literal cell types, no formula cells, macros, external references, or live hyperlinks. JSON stays typed and omits provenance by default.
- **Storage/import:** parse into typed records; bound file size, selector complexity, object keys, nesting and counts; handle unsafe object keys without merging into prototypes. Imported configs have no execution authority, must preview and gain consent separately, and cannot store code or credentials. Migrate transactionally and test adversarial corrupt records. Avoid raw scraped strings in logs; local clear-history operations are scoped and verifiable.

## Proposed testable resource limits

Starting defaults for approval/calibration, not measured performance: 10 collection steps (hard cap 100 per approved run), 1 second between repeated actions (min 500 ms), 15-second wait per step, stop after two no-growth steps and 5 minutes total per run, 10,000 committed rows, 100 columns, 16 KiB per cell, and batches up to 200 rows or 256 KiB, whichever comes first. Start a scan with a 50,000-node budget and yield frequently; cap preview sample and memory/cache growth independently. Preflight export byte/cell budget and make limits visible. Oversize or aborted work yields an actionable error/partial status, never a silent success. Do not automatically retry a click with uncertain effects. Tune against controlled fixtures and actual browser measurements, while retaining explicit hard caps.

## Release evidence required

Verify production manifest and network silence on controlled scenarios. Assert blocked-origin behavior, restricted page refusal, no extraction after stop/expiry/cross-origin redirect, forged or stale message rejection, XSS-safe rendering, imported-config validation, risky formula and filename handling, quotas and worker interruption. No open critical release issue; high risks require resolution or a documented release decision consistent with the approval gate. Provide clear reporting instructions and a responsible-extraction reminder in user docs. Do not imply that the extension authorizes collection or protects exports after saving.
